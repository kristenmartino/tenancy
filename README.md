# Tenancy (web)

Next.js 16 + Tailwind 4 frontend for the [tenancy-api](https://github.com/kristenmartino/tenancy-api) residential lease extraction prototype. Upload a PDF, inspect extracted fields and available source references, resolve exceptions, and ask questions about the extraction. Model output and citations require human verification.

Live: [tenancy-opal.vercel.app](https://tenancy-opal.vercel.app) · API: https://tenancy-api-production.up.railway.app

## What's here

| Route | What it does |
|---|---|
| `/` | Lease list + upload form. Drop a PDF URL or upload a file → kicks off extraction → redirects to detail. |
| `/leases/[id]` | Side-by-side PDF viewer + structured extraction + exception queue + grounded Q&A. Fields with source references can navigate to the PDF page; resolved text coordinates enable a highlight. |

The UI implements four panels: PDF viewer, extraction, exception resolution, and Q&A. Source references can be missing or incorrect; text highlighting depends on backend matching, and checkbox/signature geometry is deferred. Bbox overlays driven by extraction-time `bboxes: BoundingBox[]` from the backend (OCR-anchored via pdfplumber — see [tenancy-api#26](https://github.com/kristenmartino/tenancy-api/pull/26)). Multi-line values render Word-style, blank-template fields anchor on the labeled blank line, not the section header.

## Stack

- Next.js 16 (App Router), React 19, TypeScript 5
- Tailwind 4
- `react-pdf` for the PDF viewer (canvas-only, no text layer — overlays are absolutely-positioned divs driven by bbox coordinates)
- Server components by default; `"use client"` only where state requires it (`LeaseDetailLayout`, `PdfViewer*`, `UploadForm`, `Extraction`, `QAPanel`, `ExceptionRow`)

## Configuration

`NEXT_PUBLIC_TENANCY_API_BASE` overrides the API base URL (defaults to the live Railway deploy).

```bash
npm install
npm run dev          # localhost:3000
NEXT_PUBLIC_TENANCY_API_BASE=http://localhost:8000 npm run dev  # point at local backend
```

## Deploying

Vercel auto-detects Next.js — push the repo, import it in Vercel, no env vars required for the default API target.

## Status

Q&A receives stored extraction fields, not the exception queue or review decisions. Its suggested questions cover lease values; use the queue for review status. Citation buttons resolve field paths against the stored extraction and use that field’s page and highlight coordinates, ignoring model-generated pages and snippets. Unknown field paths, section-level references and absent sources cannot create PDF links. Citations to reviewer-corrected fields identify the PDF as the original source, which may still show the previous value. This structural check does not verify that a field supports the answer. Saving a review decision clears the displayed answer and pauses Q&A until the refreshed fields load. Inferred boolean values are labeled as model interpretations with the stored source excerpt; they can still be wrong.

The prototype implements ingest → extract → validate → review queue → Q&A, with text highlighting where source matching succeeds. Extraction accuracy and citation coverage have not been established on a labeled evaluation set. Confidence values are model reports, not calibrated probabilities. Extractions are saved before review; the readiness flag summarizes blocking exceptions and does not export to a property-management system. Demo recording remains pending. Productize gates (multi-tenant auth, eval set, queue infra, observability) explicitly deferred per the case-study framing — see [`STATUS.md`](STATUS.md) for the full roadmap and recent decisions.
